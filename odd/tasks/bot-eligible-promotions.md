# Bot-eligible promotions

Cross-repo program: promotions apply in the WhatsApp chatbot only when enabled for the bot at creation; every promotion type must eventually be supported.
Chatbot repo coordinates; backend (session 01a14144) and frontend (session 01a1417e) implement in their own repos. No PRs; merge to local main, owner pushes.

## Specs

- S1 — Owner idea, verbatim: "Cuando creas la promocion puedes permitir que el bot ocupe la promocion, pero evidentemente esto solo serviria para promociones automaticas". A per-promotion "available for the chatbot" flag set at creation/edit; only automatic promotion types the backend can compute may enable it.
- S2 — Owner answer "1. estoy de acuerdo" to the rule: a promotion not enabled for the bot is ignored by `evaluate-cart` (customer buys at regular price) instead of blocking the order with `needs_human_review`.
- S3 — Owner, verbatim: "todos los tipos de promocion se ocupan, no importa por donde empecemos, se van a tener que hacer todos." Every promotion type gets backend evaluation for the bot, one type per unit with tests; the model never computes discounts.
- S4 — Proposed and accepted as plan: coupon-code promotions validated by the backend; discretionary (manual) discounts via operations-channel human approval, reusing the shipping-approval pattern.
- S5 — Chatbot shows the applied promotion (`appliedPromotionTitle`) in the cart and order summary.
